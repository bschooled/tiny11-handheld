# Autounattend.xml Generation Fixes - 2026-01-22

## Summary

Fixed **4 critical bugs** in `modules/Autounattend.psm1` that prevented successful Windows installation. All builds now generate properly structured `autounattend.xml` files that match the working reference from Windows Unattend Generator.

## Root Cause Analysis

The builds were **succeeding** (ISOs generated successfully), but the **generated autounattend.xml was broken** and would cause installation failures during OOBE with "computer restarted unexpectedly" errors.

### Bug #1: Broken ExtractScript PowerShell Command
**Issue:** PowerShell variables (`$xml`, `$sb`) not properly escaped in here-string  
**Symptom:** Generated XML showed `$xml = [xml]::new()` instead of `\$xml = [xml]::new()`  
**Impact:** Scripts never extracted to disk during setup  
**Fix:** Added backtick escapes: `` `$xml``, `` `$sb`` in PowerShell here-string (Line 648)

### Bug #2: Duplicate Specialize.ps1 Execution
**Issue:** Specialize.ps1 referenced in BOTH `Microsoft-Windows-Deployment` AND `Microsoft-Windows-Shell-Setup` RunSynchronous sections  
**Symptom:** Script attempted to run twice during specialize phase  
**Impact:** Potential race conditions, duplicate execution  
**Fix:** Removed duplicate from Shell-Setup, kept only in Deployment component (Line 530-545)

### Bug #3: Missing ExtractScript in Extensions Section
**Issue:** Extensions section had `<File>` elements but no `<ExtractScript>`  
**Symptom:** Windows Setup had no mechanism to extract embedded scripts  
**Impact:** All scripts remained embedded in XML, never written to disk  
**Fix:** Added complete ExtractScript with proper encoding logic (Line 600-625)

### Bug #4: Missing DefaultUser.ps1 File
**Issue:** RunSynchronous Order 4 referenced `DefaultUser.ps1` but it was never generated in Extensions section  
**Symptom:** "File not found" error during specialize phase  
**Impact:** Setup crashed when trying to execute non-existent script  
**Fix:** Added `DefaultUser.ps1` generation (always generated, even if minimal) (Line 490-575)

## Technical Details

### ExtractScript Functionality
The ExtractScript is executed during the specialize phase (RunSynchronous Order 1) and:
1. Loads the unattend.xml file from `C:\Windows\Panther\unattend.xml`
2. Iterates through all `<File>` elements in the Extensions section
3. Detects the proper encoding based on file extension (.ps1 → UTF-8, .reg → UTF-16LE BOM, etc.)
4. Extracts each script to its specified path (e.g., `C:\Windows\Setup\Scripts\Specialize.ps1`)
5. Creates parent directories as needed

### RunSynchronous Execution Order (Specialize Pass)
1. **Order 1:** ExtractScript - Extracts all embedded scripts to disk
2. **Order 2:** Specialize.ps1 - System-wide registry modifications
3. **Order 3:** Load DefaultUser registry hive (`reg.exe load "HKU\DefaultUser"`)
4. **Order 4:** DefaultUser.ps1 - Configure registry defaults for all new users
5. **Order 5:** Unload DefaultUser registry hive (`reg.exe unload "HKU\DefaultUser"`)

### DefaultUser.ps1 Purpose
Runs during specialize phase with the DefaultUser registry hive loaded. Configures registry settings that will be inherited by ALL new users created on the system, including:
- Copilot settings
- File extension visibility
- SmartScreen settings
- App suggestion settings
- Bing search results settings
- Sticky Keys settings
- RunOnce command to execute UserOnce.ps1 on first login
